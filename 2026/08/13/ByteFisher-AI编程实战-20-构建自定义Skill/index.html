ByteFisher AI 编程实战（二十）：构建自定义 Skill——让AI拥有专属能力

发表于 2026-08-13 分类于 AI Waline：
本系列第20篇，共21篇。实战讲解如何构建自定义 AI Skill，涵盖 OpenCode Agent 开发和 Claude Code Skill 开发，从指令定义到工具封装再到发布复用。

MCP 提供了标准化的工具接口，Skill（技能）则是在这之上构建的更高层次的 AI 能力包——它组合了指令、工具、上下文，让 AI 能够完成一个特定领域的复杂任务。

一、什么是 Skill

Skill 是一组预定义的指令和工具的集合，告诉 AI “如何完成某类任务”。

类比 说明
传统编程 一个库/包，封装了特定功能，可复用
AI Skill 预定义的指令+工具，让 AI 掌握特定领域技能
与之对比的 MCP 标准化的工具接口（底层通信协议）
Skill 在工具之上构建的任务模式（上层能力封装）

一个 Skill 通常包含：系统指令、可用工具列表、输入输出格式、工作流程、边界约束。Skill 可以被理解为”AI 时代的函数”——封装特定能力，可供复用和组合。

3.3 Skill 与 MCP 的协同

Skill 和 MCP 不是替代关系，而是分层协作：

例如一个”Unity 性能优化 Skill”可能组合使用：

  • MCP File System：读取项目脚本
  • MCP SQLite：读取性能数据
  • 自定义指令：Unity 性能分析的方法论

四、Skill 设计原则

原则 说明 反例
单一职责 一个 Skill 只做一类事 “通用编程助手”（太宽泛）
明确边界 清楚说明能做什么和不能做什么 “帮你写代码”（边界模糊）
可组合 Skill 之间可叠加使用 所有功能塞到一个 Skill 中
可测试 有明确的输入输出预期 “优化代码”（太模糊）

五、Skill 与 Agent 的关系

Skill 和 Agent 是不同抽象层次的概念：

概念 类比 职责
Agent 一个员工 决策者：理解任务、制定计划、协调执行
Skill 该员工的专业技能 告诉员工”这类任务怎么做”
Tool 员工使用的工具 具体的执行能力（读文件、写代码）

一个 Agent 可以使用多个 Skill。例如 “Unity 开发 Agent” 可以同时加载 “代码规范 Skill” 和 “性能优化 Skill”。

八、Skill 的局限性

Skill 虽然强大，但也有一些注意事项：

局限性 表现 应对
不擅长”创造” 只能按指令办事，不能发明新模式 需要人类设计新的 Skill
上下文消耗 指令越长，可用 Token 越少 保持指令简洁，控制在 500 字以内
冲突风险 多个 Skill 的指令相互矛盾 测试 Skill 组合兼容性
维护成本 Skill 需要随工具版本更新 定期检查和更新

九、Skill 调试方法

开发 Skill 后如何验证它是否正常工作：

方法 操作 预期结果
直接测试 加载 Skill 后问一个典型问题 回答遵循 Skill 定义的规则
边界测试 问 Skill 范围之外的问题 拒绝回答或明确说明边界
对比测试 加载/不加载 Skill 对比同一问题的回答 加载 Skill 后的回答更专业
压力测试 连续问 5 个不同问题 风格和格式一致
组合测试 同时加载两个 Skill 两个 Skill 的规则同时生效

本章小结

  • Skill 是预定义的指令+工具集合，让 AI 掌握特定领域能力——可理解为”AI 时代的函数”
  • OpenCode Agent 通过 JSON 配置定义角色、工具、行为约束
  • Claude Code Skill 用 Markdown + Front Matter 定义，更强调自然语言描述
  • Skill 与 MCP 是分层关系：Skill 定义任务模式，MCP 提供工具接口
  • 好的 Skill 包含：身份定义、行为约束、质量要求、工作流程
  • 构建 Skill 的流程：发现问题 → 提取模式 → 编写 → 测试 → 复用
  • Skill 正在成为 AI 时代的”复用单元”，本质是领域知识的可编程封装
